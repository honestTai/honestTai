## 两种视角，不混为一谈

1. **留存事件历史**：按当前仍保留 Star 的用户最初收藏时间、目前可见 Fork 的创建时间绘制阶梯图。可立即查看，但**不是过去各日的净总量或真实净增长**。已取消的 Star、删除或不可见的 Fork 无法追溯。图底部显示采集事件数与仓库总量，二者可能不同；取消旧 Star 后，重建曲线也会变化。
2. **每日实测总量**：记录成功采集时 API 的 Star / Fork 总数，自 **2026 年 10 月 6 日**开始。没有伪造回填；仅有一个观测日时只画一个点，不假装已有趋势。同日重跑更新当天记录。漏采日期不算观测值，水平连线只是沿用上次观测值的视觉连接。

主页汇总包含 honestTai 的所有公开仓库，包括 Fork 与个人主页仓库。各仓库 Star 相加**不等于独立用户数**。Open issues + PRs 同时包含未关闭的 Issue 和 Pull Request。日期采用 UTC，每日计划于 **UTC+8 09:23** 采集；GitHub 调度可能延迟，不是实时数据。各接口依次请求，并非同一瞬间的原子快照。

## 自动化与隐私

- 只查询公开用户仓库接口，并显式过滤私有仓库。
- 新的公开仓库、Fork 和归档仓库会自动进入目录与统计；新项目 README 中的图表仍需添加一次。
- 仅保存事件时间戳与公开汇总信息，不保存收藏者账号、邮箱、Token 或私有项目资料。
- 自动任务只使用本仓库短期 `GITHUB_TOKEN`，不需要个人 PAT；仅对主页仓库授予写权限。
- 接口采集必须全部成功才生成文件；失败不会把数据归零。并发任务串行处理，不强制推送。
- SVG 随仓库存储，不依赖第三方统计图片服务。图片缓存可能延迟；以图中日期和 Actions 状态为准。
- 仓库后续改名、删除或转私有时，原公开期间记录的历史计数仍保留，当前目录只显示目前公开的仓库。
- GitHub 可能因仓库长期无活动停用定时任务，可在 Actions 重新启用或手动运行 **Refresh public portfolio**。
